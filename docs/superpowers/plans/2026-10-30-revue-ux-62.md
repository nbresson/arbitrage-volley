# Revue UX : plan d'implémentation des 62 propositions

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** corriger les 62 problèmes relevés par la revue UX (4 P0, 24 P1, 27 P2, 7 P3), sans régression.

**Architecture :** SvelteKit 3 statique + Supabase. Chaque tâche touche une partie du site, avec ses tests (Vitest unitaires dans `tests/unit`, intégration contre la base de test dans `tests/integration`). Les règles métier vont dans des fonctions pures testées (`src/lib/**.ts`), les écrans les appellent. Trois petites migrations SQL (tâches 3, 7, 14), appliquées en test pendant le chantier, en prod seulement à la mise en ligne.

**Tech Stack :** SvelteKit 3, Svelte 5 (runes), TypeScript, Supabase (PostgreSQL, RLS), Vitest 5 + Testing Library, axe-core.

**Spec :** [docs/superpowers/specs/2026-10-30-revue-ux-62-propositions.md](../specs/2026-10-30-revue-ux-62-propositions.md) (numéros 1 à 62 ci-dessous = numéros de la spec).

## Global Constraints

- Branche de travail : `revue-ux` (créée depuis `main`). Fusion, envoi et migrations en prod : uniquement avec l'accord de l'utilisateur, à la tâche 22.
- Tout texte visible en français, sans « Something went wrong » : chaque erreur dit ce qui n'a pas marché et propose une action (composant `MessageErreur.svelte`, prop `onreessayer`).
- Toute couleur passe par `src/lib/styles/tokens.css` (`--papier` = surface ; `--sur-fonce` = texte sur aplat foncé ; `--trait` = trait sur surface). Une couleur nouvelle est d'abord ajoutée à DESIGN.md (`tests/unit/tokens.test.ts`).
- Cible tactile : 44 px de haut au moins pour tout contrôle (bouton, lien d'action, onglet, résumé de `<details>`, case).
- Fonctions SQL `security definer` : `set search_path = public`, `revoke … from public, anon`, `grant … to authenticated`. Une migration appliquée ne se modifie plus.
- Les formateurs ne lisent jamais les séances `examen_entrainement` d'un stagiaire.
- Commits en français, terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Fichiers écrits depuis Python : `open(..., newline='')` (fins de ligne LF). Long script : fichier dans le scratchpad, pas de here-document Bash.
- Commandes : `npm test`, `npm run test:integration`, `npm run check`, `npm run build`, `npm run db:dev`.

## Review Focus

1. **Examen officiel hors ligne au moment de la fin du temps** : la réponse cochée doit partir avec les autres, et l'écran « Temps écoulé » ne doit jamais clore la tentative avant l'envoi de la file (tâche 10, test `fin du temps hors ligne : réponse cochée gardée et envoyée au retour`).

3. **Recherche « Cas 3.35 » depuis l'onglet FIVB** : le cas doit apparaître (tâche 12, test `une recherche active couvre toutes les sources`).
4. **Stagiaire jamais actif dans le tri « les plus faibles d'abord »** : il doit apparaître en tête (tâche 14, test `sans séance : en tête`).
5. **Retour arrière depuis une fiche du Casebook** : l'onglet Casebook et la recherche doivent être restaurés (tâche 12, test `vue et recherche relues depuis l'adresse`).
